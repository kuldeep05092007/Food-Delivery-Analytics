# Viva / Interview Questions (Beginner Level)

**1. What is this project about, and is the data real?**
It analyses food delivery orders to understand restaurant performance, city demand, delivery speed, cancellations, payments and busy times. The data is synthetic (generated by code), so it is for learning, not real company data.

**2. Why did you generate a messy dataset instead of a clean one?**
Real data is rarely clean. The file has duplicates, missing values, inconsistent text and outliers so we can practise the cleaning steps that data analysts do every day.

**3. Why do you standardize text before removing duplicates?**
`delhi` and `Delhi` look like different values to Python, so two copies of the same order would not be detected as duplicates. After standardizing text, the copies become identical and `drop_duplicates()` removes them.

**4. How did you handle missing values, and why not delete all of them?**
It depends on the column. Missing City or Payment_Method became `Unknown` (the order is still valid). Missing Discount became 0. Preparation time used the restaurant's median. Delivery time and rating were left missing, because cancelled orders have no delivery and many customers do not rate. Deleting all rows with any missing value would throw away valid orders and bias results.

**5. What is the IQR method for outliers, and did you delete outliers?**
IQR = Q3 - Q1. A value is an outlier if it is below Q1 - 1.5 x IQR or above Q3 + 1.5 x IQR. We only flagged outliers. We deleted or corrected only impossible values (for example an order of Rs 99,999 or a 520-minute delivery). A Rs 5,000 party order is unusual but real, so it stays.

**6. What is the difference between Order_Value, Net_Order_Value and Total_Order_Amount? Is Order_Value the company's revenue?**
Net_Order_Value = Order_Value - Discount. Total_Order_Amount = Net_Order_Value + Delivery_Fee. Order_Value is the customer's food bill, not company revenue. A platform earns commission and fees, which are not in this data.

**7. How do you treat cancelled orders in financial calculations?**
They are excluded from money totals, average order value and delivery-time statistics because no completed sale happened. They are included when calculating completion rate and cancellation rate.

**8. How is Delivery_Delay_Min calculated and when is an order late?**
Delivery_Delay_Min = Delivery_Time_Min - Expected_Delivery_Time_Min. If it is above 0, `Is_Late_Delivery` is 1. It is calculated only for delivered orders, so the late rate is the share of delivered orders that were late.

**9. Why is the mean order value higher than the median, and which should you report?**
A few very large orders pull the mean up. The median is not affected by extreme values, so it describes a typical order better. Good practice is to report both.

**10. Explain how the dashboard filters work and how it avoids crashing on empty results.**
The sidebar widgets create a filtered DataFrame using conditions such as `df["City"].isin(selected_cities)` combined with `&`. KPIs and charts are calculated from that filtered DataFrame, so everything updates together. If the result is empty, the app shows a warning and calls `st.stop()`. Charts that need delivered orders show an info message when there are none.
