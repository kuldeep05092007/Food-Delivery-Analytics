# Food Delivery & Restaurant Performance Analytics

A beginner-friendly, end-to-end Data Analysis project using **Python, NumPy, Pandas, Matplotlib, Plotly and Streamlit**.

> **Data note:** All data is **synthetic** (generated by `generate_dataset.py`). It is **not** real company data. Restaurant names are fictional. Use it for learning and portfolio demonstration only.

This is a **food delivery analytics** project (orders, delivery time, cancellations, ratings). It is not a retail sales project.

## Business questions

1. Which restaurants and cuisines perform best?
2. Which cities generate the most orders and order value?
3. What is the average delivery time?
4. How do discounts relate to order value?
5. What percentage of orders are late or cancelled?
6. Which payment methods are used most?
7. Which days and time periods receive the most orders?

## Installation

You need **Python 3.9 or newer**. Open a terminal **inside the `food_delivery_analytics` folder**.

```bash
# 1. (Recommended) create a virtual environment
python -m venv venv

# 2. Activate it
#    Windows (PowerShell / CMD):
venv\Scripts\activate
#    macOS / Linux:
source venv/bin/activate

# 3. Install the libraries
pip install -r requirements.txt
```

## Run the dashboard

The two CSV files are already included, so you can start straight away:

```bash
streamlit run app.py
```

The dashboard opens in your browser at `http://localhost:8501`.

## Run the notebook

```bash
jupyter notebook notebooks/food_delivery_analysis.ipynb
```

Use **Kernel > Restart & Run All** to run every cell. The notebook already contains its outputs, so you can also just read it.

## Rebuild the data from scratch (optional)

```bash
python generate_dataset.py     # creates data/food_delivery_orders.csv  (1,500 rows)
python clean_data.py           # creates data/cleaned_food_delivery_orders.csv
```

The random seed is fixed, so you get the same dataset each time. (Different NumPy versions can rarely change random numbers; if that happens, your numbers may differ slightly from the report.)

## Dataset columns (raw file)

| Column | Meaning |
|---|---|
| Order_ID | Unique order number (e.g. FD100001) |
| Order_Date, Order_Time | Date (YYYY-MM-DD) and time (HH:MM) the order was placed. April to September 2026 |
| Customer_ID | Customer code |
| City, Restaurant_Name, Cuisine_Type | Where, which restaurant, which cuisine |
| Order_Value | Food bill in rupees **before** discount |
| Discount | Coupon discount in rupees |
| Delivery_Fee | Delivery charge in rupees |
| Payment_Method | UPI, Cash on Delivery, Credit Card, Debit Card, Digital Wallet, Net Banking |
| Order_Status | Delivered, Cancelled or Refunded |
| Preparation_Time_Min | Minutes the kitchen took |
| Delivery_Time_Min | Total minutes from order placed to delivery (includes preparation) |
| Expected_Delivery_Time_Min | Time promised to the customer |
| Customer_Rating | 1 to 5 (many are missing) |

## Calculated columns (cleaned file)

| Column | Definition |
|---|---|
| Hour | Hour of the order (0-23) from Order_Time |
| Order_Month | Month as `YYYY-MM` |
| Day_of_Week | Monday ... Sunday |
| Time_Period | Morning, Lunch, Evening Snacks, Dinner or Late Night |
| Net_Order_Value | `Order_Value - Discount` |
| Total_Order_Amount | `Net_Order_Value + Delivery_Fee` (what the customer is charged) |
| Delivery_Delay_Min | `Delivery_Time_Min - Expected_Delivery_Time_Min`. Positive means late. Delivered orders only |
| Is_Late_Delivery | 1 if the delay is more than 0 minutes, otherwise 0. Empty if the order was not delivered |
| Is_Order_Value_Outlier, Is_Delivery_Time_Outlier | 1 if the value is an IQR outlier (flag only, row is kept) |

## Important rules used in this project

* **Order value is not company revenue.** It is the customer's food bill. A delivery company earns commission and fees, which are not in this dataset.
* **Cancelled and refunded orders are not sales.** All money totals and averages, delivery times and late rates use **Delivered** orders only. Cancelled orders are still counted for completion rate and cancellation rate.
* **We do not silently delete messy rows.** Every issue has a decision (correct, keep, flag or exclude). See `docs/PROJECT_REPORT.md`.

## Dashboard features

* **6 KPI cards:** Total Orders, Delivered Orders, Completion Rate, Average Order Value, Average Delivery Time, Late Delivery Rate
* **8 charts:** monthly trend, orders by city, cuisine popularity, status donut, top restaurants, actual vs expected delivery time, orders by hour, ratings distribution
* **Extra insights (expander):** orders by weekday, payment methods, discount vs order value
* **Filters:** date range, city, cuisine, order status, payment method (everything updates together)
* **Order table** with search box and **CSV download** of the filtered data
* Friendly messages for a missing data file, an incomplete date range and filters that return no orders

## Troubleshooting

| Problem | Fix |
|---|---|
| `Data file not found` in the dashboard | Run `python generate_dataset.py` then `python clean_data.py` from inside the project folder |
| `streamlit` is not recognised | Activate the virtual environment, or run `python -m streamlit run app.py` |
| Notebook cannot find the data | Start Jupyter from the project folder or from `notebooks/` |
| Dashboard shows "No orders match" | Select more cities, cuisines, statuses or payment methods |

## Limitations

* Synthetic data: patterns such as busy dinner hours and slower peak-time deliveries were built into the generator, so the findings show *method*, not real-world truth.
* Restaurants appear in all cities (like chains). Real data would have restaurant-city pairs.
* Only six months, so yearly seasonality cannot be studied.
* The dashboard was tested with Streamlit's automated test tool, not by opening a browser window in the build environment. Please run it once on your computer and check that it looks right.
